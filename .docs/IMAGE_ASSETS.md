# Public image assets and project carousel

The project showcase uses all 80 images supplied in `assets/PROJECTS/`: 79 PNG screenshots and one U-Cash JPEG. `scripts/optimize-portfolio-images.mjs` exports WebP copies into `public/projects/gallery/` and generates `src/lib/projectGallery.ts`. The original archive stays untouched and Git-ignored. Production rendering needs only the public assets and generated catalog.

Full-resolution gallery copies total 5,269,216 bytes, compared with 11,969,142 bytes for their originals (56% smaller). Separate 680px maximum thumbnails serve the decorative carousel, avoiding downloads of the full screenshots. The gallery manifest records every file, project, dimensions, and measured byte counts.

`ProjectBackground` interleaves projects into six horizontal strips behind Featured Projects and More Projects. Alternate rows reverse direction, with 84–139 second loops. Two identical strip groups provide a continuous seam. A shaded, gently tilted sticky wall follows the showcase while the cards retain their opaque surfaces. The wall is inert, hidden from assistive technology, and cannot intercept pointer input. Images load lazily and decode asynchronously. Intersection/visibility observers stop animation offscreen or in hidden tabs; global Pause, reduced motion, and an open project modal also stop the strips. No frame-by-frame JavaScript or new animation runtime is used.

The displayed portfolio PNGs, including project logos, sample artwork and the About portrait, now use WebP. Across 51 images the measured total dropped from 5,818,354 to 1,931,480 bytes (67% smaller). The converter chooses the smaller lossless/near-lossless WebP encoding, retaining dimensions and transparency. Existing genuine SVG files stay SVG; putting raster screenshots inside SVG would not make them vector images. The original certificate PNG download and Next.js's convention-based `src/app/icon.png` remain intact. Source PNG imports under `src/app/images/` are preserved as originals, while the project detail routes now serve public WebP copies.

Before removing a converted public PNG, the script saves its original bytes under the ignored `.taste-skill/png-originals/public/` directory. `public/projects/image-optimization.json` records the replacement URLs and aggregate sizes. The standalone sample generators now encode PNG source art directly to WebP through `scripts/project-samples/copy-image.mjs`; original `PROJECTS/` files remain unchanged. PALDEX's original `Home.css` and existing vector/font/video assets are preserved.

To regenerate after changing the local source archive, run `node scripts/optimize-portfolio-images.mjs`. To regenerate standalone samples, run `node scripts/generate-project-samples.mjs`. These use the installed Sharp image library; they do not start the reference applications. Generated images/catalogs are included in the portfolio so deployment needs neither ignored source folder.
